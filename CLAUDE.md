# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

QuizRunOnline ("Endless Runner 3D"): a multiplayer 3D obstacle-runner where hitting obstacles triggers quiz questions. Unity **2022.3.62f3**, Photon Fusion 2 (**Shared mode**), Firebase Auth/Firestore, TextMeshPro. Game code is in `Assets/Scripts`; comments and Debug logs are mostly in Vietnamese.

## Build / run / test

There is no CLI build, lint, or test setup: no test assemblies and no `.asmdef` files in game code. Everything is done through the Unity Editor:
- Open the project with Unity 2022.3.62f3 and press Play. Compile errors show in the Editor console.
- Open `AccountScene` first for the real flow. `LobbyScene` can be opened directly in the Editor because `AuthGate.bypassInEditor` is on.
- Multiplayer testing needs two running instances (e.g. a Windows standalone build plus the Editor). The Photon App ID is in `Assets/Photon/Fusion/Resources/PhotonAppSettings.asset`.
- `.csproj`/`.sln` files at the repo root are generated by Unity; don't edit them.

## Scene flow

`AccountScene` (login) → `ShopScene` (optional) or `LobbyScene` (rooms) → `RaceScene` (race). Names are constants in `Core/SceneNames.cs` and must match Build Settings. `RaceExit` returns to the lobby.

- **LobbyScene** is room creation and joining: `Lobby/LobbyManager`, `Network/Room/*`, `Network/Player/*` (PlayerRoomData, PlayerRowUI, ...).
- **RaceScene** is everything else: spawn players (`RaceScenePlayerSpawner`), obstacles, buffs, quiz, score, finish line, spectator, summary.
- When adding or changing a script, decide which scene it lives in. Some singletons only exist in one scene (e.g. `SpawnEffect.Instance` only in RaceScene).

## Script folders (`Assets/Scripts`)
- `Core/` shared by every scene: `SceneNames`, `PlayerContext`, `SafeAreaFitter`, `UI_ConfirmDialog`, `UI_Notification`, `FrameRateSettings`, `FpsCounter`.
- `Backend/Account/` Firebase auth and profile. `Lobby/` `LobbyManager`. `Menu/` and `Shop/` hold the UI of those scenes.
- `Network/` Fusion code (rooms, players, `Spawner/`). `Spawning/` pure planning logic (`SpawnPlanner`, `SpawnProfile`).
- `Race/World/` map and track pooling (`MapSpawner`, `TracksSpawner`, `WorldFocus`, `RaceTrackConfig`, `WorldCurvature`). `Race/HUD/` in-race UI (speedometer, lives, countdown, coin counter, leave button).
- Other race features keep their own folder: `Player/`, `Camera/` (includes `RaceSpectatorManager`), `Question/`, `Buff/`, `Items/`, `Effects/`, `Inventory/`, `PlayerScore/` (includes `CoinCalculator`), `RaceFinish/`, `RaceProgress/`, `RaceSummary/`, `DistanceIndicator/`.
- Move or rename scripts inside the Unity Project window (or with `git mv` on the file **and** its `.meta`) so GUIDs stay valid.

## Rendering and performance
- The project has the URP package, but **no URP asset is assigned** in Graphics or Quality settings, and the Profiler shows Built-in pipeline passes (`RenderForwardOpaque`). Treat it as the **Built-in Render Pipeline**: URP-only features (Render Scale, SRP Batcher, Volumes) do not apply. Check this before relying on them.
- Android defaults to quality level **Medium** (VSync on), which locks the game to 30 FPS when a frame takes over 16.6 ms. `Core/FrameRateSettings` turns VSync off and sets `targetFrameRate = 60` on Android devices only.
- `Core/FpsCounter` shows FPS in the Editor and Development Builds only. It uses uGUI because IMGUI (`OnGUI`) allocates every frame and skews GC Alloc readings in the Profiler.
- Keep per-frame code allocation-free (no `new`, string concatenation, or `foreach` over `IReadOnlyList`/interfaces in `Update`/`LateUpdate`). Check GC Alloc in the Profiler (CPU Usage > Hierarchy).

## Architecture

### Networking lifecycle (spans several files)
- `LobbyManager` is a `DontDestroyOnLoad` singleton that owns the single `NetworkRunner`. It connects to the Fusion session lobby on start, then `CreateRoom`/`JoinRoom` call `StartGame(GameMode.Shared)`. It must survive into `RaceScene`, and a duplicate is destroyed in `Awake` if you return to the lobby.
- Leaving a room: `LeaveRoomAsync()` shuts down the runner, calls `PlayerContext.Clear()` and reconnects to the lobby. Returning to the Account screen: `TeardownAsync()`.
- `RoomManager` (a NetworkObject spawned by the room creator) loads `RaceScene` through `Runner.LoadScene` once every `PlayerRoomData.IsReady`, finding the build index by scene path.
- Each player spawns a `PlayerRoomData` networked object in the lobby. It carries name, character index and skin index, and `RaceScenePlayerSpawner` reads it in `RaceScene` to spawn that player's character prefab from `CharacterCatalog`. Appearance is passed via `onBeforeSpawned` to `CharacterSkin.SetAppearance` so every client sees the same skin.
- `RaceStartController` runs the shared countdown. The master client (`IsSharedModeMasterClient`) owns the `TickTimer`, and every client fires the static `OnRaceStarted` event.
- Shared-mode authority pattern: each player's own character has `StateAuthority` and writes its networked state. Proxies only read, e.g. `PlayerNetworkState` drives the remote Animator from `[Networked]` counters. Check `Object.HasStateAuthority` before mutating, e.g. `Buff.ApplyBuff` and `NotifyJump`.
- Shared race state lives in scene NetworkObjects with state authority on the master: `LeaderboardManager` (a `NetworkDictionary<PlayerRef, PlayerRaceEntry>` holding score, coins, deaths and name, written via RPC), `RaceResultManager` (finish order, RPCs) and `ObstacleSpawnPointGenerator`.

### Obstacles
`ObstacleSpawnPointGenerator` (master only) generates a networked array of spawn **data** (`NetworkArray<SpawnEntry>`, capacity 192; it must cover `spawnAheadDistance`, roughly 18 slots per 100 m, and changing it changes the network layout so every client must be rebuilt) ahead of the leader. Spawn data comes from `RacePlayersRegistry.GetLeadingPlayer()`/`GetTrailingPlayer()`, which skip eliminated players. It also respects `RaceTrackConfig` finish-line clearance. `LocalObstacleSpawner` on each client instantiates **local, non-networked** obstacle GameObjects near the local player from that data. So obstacles are not NetworkObjects, and the prefab index must match `obstaclePrefabs` order in the spawner.

What goes into each row is planned by `Spawning/SpawnPlanner` (pure static logic, no MonoBehaviour or networking, Subway-Surfers style: difficulty rises with race progress, and every row must keep a reachable lane from the previous one). It is driven by a `SpawnProfile` asset, and `CoinPatternBuilder` expands coin patterns into single coins. The generator and `LocalObstacleSpawner` must reference the **same** `SpawnProfile` asset. The generator also has a debug path that calls `SpawnPlanner.Simulate` to check a plan without running a race.

### Quiz and scoring pipeline
- Hitting an obstacle: `QuestionTrigger` calls `QuestionManager.Instance.ShowQuestion(...)`. The manager loads `Resources/questions.json` (each question has a `category`: `math` or `english`) and picks from the pool matching the trigger's `QuestionCategory` (set per prefab: `MathQuestion` = Math, `EnglishQuestion 1` = English, `Any` = mixed) through a shuffled bag, so a question does not repeat until its pool is exhausted. It then runs the answer timer, applies speed buff / slow debuff, and reports an `AnswerResult`.
- `PlayerScoreManager` holds the **local** player's total score. Every source (quiz, coin, rank bonus) must go through its private `AddScore()`; add a new source by extending the `ScoreSource` enum and adding a rule asset (see the class doc comment). Rules are ScriptableObjects (`IScoreRule<TInput>`: `QuizScoreRule`, `RankBonusRule`) in `Assets/Data/ScoreRules`.
- `PlayerScoreManager` deliberately has **no Fusion dependency**. `PlayerScoreNetworkReporter` bridges it, plus `CoinCalculator` and `PlayerLives`, to `LeaderboardManager.ReportStats`. Keep that separation.

### Buffs
`Buff` is an abstract ScriptableObject (assets in `Assets/Data/Buffs`) with `OnFirstApplied` and `OnStackChanged`. `PlayerBuffManager` handles stacking and expiry, and `BuffContext` is a small key/value bag shared across hooks. Concrete buffs are in `Buff/Types of Buffs`; pickup items are in `Items/BuffItems`.

### Accounts and backend
`AuthService` (Firebase Auth, Google Sign-In on Android) and `UserProfileService` (Firestore `users/{uid}`, cached in `Current`) are `DontDestroyOnLoad`. `BackendMode.UseFirebase` is **false in standalone Windows builds** (local in-memory login and a random `Player_NNN` name) and true in the Editor and Android. `AuthGate` in `LobbyScene` bounces unauthenticated users back to `AccountScene`, and `LobbyManager` checks `AuthGate.Redirecting` so it doesn't connect first.

### Misc
- `WorldCurvature` pushes global shader values (`_WorldCurveStrength`, etc.) for the curved-world look. Custom shaders depend on it.
- `PlayerContext` exposes the local player's transform, stats and inventory. Late-binding consumers subscribe to `PlayerContext.OnLocalPlayerReady` instead of searching the scene.

## Conventions
- Singletons use a static `Instance`. Cross-system communication is done with static C# events (`OnRaceStarted`, `OnRaceFinish`, `OnLocalPlayerReady`, `OnScoreUpdated`) rather than direct references. Unsubscribe in `OnDisable`/`OnDestroy`.
- Scene `NetworkObject`s may spawn after `Start()`. Code that depends on one (e.g. `LeaderboardManager.Instance`) should wait for it, as `PlayerScoreNetworkReporter` does.
- Edit scenes and prefabs through the Unity Editor; they are serialized YAML and conflict easily. Keep `.meta` files with their assets.
- **Prefabs spawned at runtime (the character prefab, via `RaceScenePlayerSpawner`) cannot hold references to scene objects.** A `[SerializeField]` pointing at a scene object (camera, `CameraShake`, UI) stays `{fileID: 0}` on the prefab, and `if (x != null)` guards then fail silently. Resolve such references at runtime (`FindObjectOfType`, `PlayerContext.OnLocalPlayerReady`, a singleton `Instance`). `PlayerCollisionHandler` finds `CameraShake` this way.
- `Assets/Photon`, `Assets/Firebase`, `Assets/ExternalDependencyManager`, `Assets/GoogleSignIn` and the many asset-pack folders are third-party; don't modify them.
